# OLED design options

Generated by `tools/oled_concepts.py` (run from the repo root). It uses the same GLCD font
and GFX primitives as `render_oled_png.py`. Every frame is driven by one simulated input
timeline run through the real rapid-trigger rules (ACT 1.20 mm, RT 0.20 mm, 4.0 mm travel):

| Frames | Input |
|---|---|
| 2–17  | `5` normal press to 2.6 mm and release |
| 20–40 | `1` rapid-trigger taps around 1.5–1.95 mm (never fully released) |
| 44–57 | `ENT` bottoms out at 4.0 mm; `7` held at the same time |

GIFs play at 66 ms/frame, half the firmware's 33 ms, so each frame is visible.
Every text draw is checked against its region, and the script exits non-zero on any overflow
(currently 0).

`contact_sheet.png` shows all options side by side.

## Full-screen layouts (pick one, or none)

- **L1 Keymap** (`L1_keymap.gif`): full-width 4×4 grid showing the real legends. Each key
  fills from the bottom with travel and turns solid on actuation; the label is XOR-drawn
  (`SSD1306_INVERSE`), so it stays readable at any fill. The header shows the layer, a live
  travel bar for the last key with an actuation tick, and the RT setting. Standby is the same
  screen, so the keymap is always visible.
- **L2 Spectrum** (`L2_spectrum.gif`): the left side shows the focused key big, its travel and
  an ACTUATED/RELEASED chip. The right side has 16 live travel bars (one group per row) with
  a dotted actuation line. A dithered bar means travelling but not actuated; a solid bar means
  actuated. Rapid-trigger resets show up as the bar flipping between solid and dithered
  without dropping to zero.
- **L3 Tach** (`L3_tach.gif`): a motorsport gauge for the focused key. The thick arc past the
  shift mark is the actuation zone, and side shift lights strobe on actuation. A compact
  grid sits on the right.

## Key-press animations for the current grid

These replace only the right-hand grid block in `renderFullScreen()` (GRID 69,15, BOX 11×9,
GAP 3). Nothing draws more than 1 px outside its own box, so no animation can reach a
neighbouring key. They need a per-key "frames since press/release" counter; `s_keyRipple`
and `s_keyReleaseDecay` already hold that kind of state.

- **A1 Plunge**: the cap top sinks 0–3 px with analog travel, turns solid on actuation, and
  overshoots 1 px on release.
- **A2 Depth + Ring**: the fill level is the travel, with actuation notches on both sides.
  A ring in the gap means actuated, so rapid-trigger taps show as the ring flickering.
- **A3 Brackets**: idle keys are drawn as corner ticks only (a much quieter screen). Travel
  pulls the ticks inward, and actuation fills the key with a 1-frame inverted flash.
- **A4 Afterglow**: the key is solid while held, then fades through a 4-frame dither after
  release.
- **A5 Safe Halo**: the smallest change to the current design. It keeps today's keycap,
  limits the halo to r=1 for 2 frames and drops the sparks.

The Python drawing functions map 1:1 onto Adafruit GFX calls (`drawRoundRect`,
`fillRoundRect`, `drawFastHLine`, `drawPixel`, and `SSD1306_INVERSE` for the XOR cases).
L3's arc needs a small precomputed cos/sin table in the firmware instead of `math`.
